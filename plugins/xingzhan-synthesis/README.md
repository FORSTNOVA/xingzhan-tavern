# 星栈合成

**文档状态（2026-10-07）：**本文是当前使用说明。功能验收历史见项目根目录 [合成实现记录](../../SYNTHESIS-PLUGIN.md)；分类准确率及样本限制见 [质量评估](../../TTS-EVALUATION-REPORT.md)。标注为具体日期的旧报告只描述该日结果。

安卓系统语音与 API 配音并列：扩展面板可点击“检测系统语音引擎”或“打开系统配音”；配音窗口顶部也可切换来源。手动检测读取当前安装的引擎及音色，标记本地/联网/未下载，并可选音色、语速和音高。系统模式直接将正文分段交给 Android TTS，不调用文本分析或中转 API；生成音频按角色卡保存，可连续播放、暂停、停止、关闭恢复及复用缓存。安装新引擎或语音包后需重新检测。API 模式保留原来的上下文配音流程。

长文本分析：整篇最多 120000 字符单位，超过 12000 自动按最多 6000 分批，逐批携带角色音色安排并合并审核。输出截断或单批片段数超限时进一步细分。界面显示进度，已完成批次自动保存，相同文本与配置重试可续接；自动分批可能增加分析调用次数。

聊天消息下点击“配音整条消息”，或选中文字后点击“选区配音”，可直接打开前台配音窗口。窗口可切换选区/全文、审核类型与角色音色、确认生成全部语音，再连续播放、暂停、停止或通过原生播放器拖动进度。关闭窗口会停止工作，已完成音频和分析自动保留，重新打开可恢复并补齐缺失片段。文本分析配置提供中转模型列表下拉选择、搜索与刷新，修改后点击保存。

独立 SillyTavern 扩展，语音与生图共用一个面板，依赖星栈酒馆 APK 提供的 `/api/android/media` 本地接口。直接安装到没有该服务接口的官方酒馆不能调用中转。

入口：扩展设置 → 星栈合成 · 语音与图片。插件保持独立，不注册官方 TTS 提供商、不修改官方生图来源，也不接管 `/imagine`。语音流程先由可配置的文本模型分析选区及附近最多 5 条消息，拆分旁白、台词、音效、背景音乐和环境音；审核页允许修正片段类型、说话角色、情绪、语气和角色音色。只对旁白和台词逐段请求 TTS，并连续播放；生成前单独确认调用。分段原文必须拼接后与选区逐字相同，否则拒绝生成。背景音类别目前只做识别和标注，不会生成音效。

酒馆页面内的「星灯」悬浮形象可拖到不遮挡聊天的位置，点击后打开快捷控制面板：进入配音窗口、带入最新回复配音、打开插图工作台、回到聊天末尾，或保存当前聊天后进入管理与更新页。点击面板右上角「−」可缩成左侧或右侧边签；边签可上下拖动，也可拖到另一侧，点击边签恢复面板。收起状态及边缘位置会保存，旋转屏幕后重新贴边。单纯打开插图工作台不会自动发起提示词或生图请求。面板可隐藏形象；要恢复，在本插件设置中勾选「在酒馆内显示星灯悬浮入口」。这是 WebView 内控件，不申请系统级悬浮窗权限，也不会覆盖其他应用。

图片生成与提示词：面板支持直接输入描述或由文本模型根据聊天内容构思提示词（支持“根据最新回复生成提示词”、“根据选区生成提示词”以及聊天消息条下的“生成插图”快捷按钮），可附加画风偏好并自动推荐比例。提示词生成调用一次文本分析模型；云端生图另行计费，本机 NPU 生图无需中转请求。两种来源都需用户手动点击“生成图片”。每次生成的图片（原图文件及比例、提示词、时间、来源）均持久化保存在当前角色卡私有目录（xingzhan-synthesis/cards/<卡标识 SHA-256>/img-<uuid>.<ext>），按角色卡完全隔离。历史卡片提供缩略图浏览、一键复用提示词与比例、查看原图及单条删除。

本机 NPU 生图入口位于“生图引擎配置 → 接入来源”。已有模型时，导入区默认收起；展开后可从手机文件中选择兼容的 QNN SD 1.5 ZIP，界面区分上传进度与解压校验。选中模型并点击“启动所选模型”会同步保存生图来源；运行中锁定模型选择，先点“停止并释放”才能切换。非方形生成会按实际尺寸重启 helper 并加载模型包内对应的 UNet 补丁；缺少补丁时明确报错。生成参数区提供普通 SD 1.5 的 20 步 / CFG 7 预设。工作台会显示本机模型的正、负提示词 token 数和超限起点；超过 77 token 时不会提交生图。自动构思提示词在本机来源下改用短英文标签，不自动拼接质量词。当前只在 OnePlus 13T / SM8750 / QNN V79 的 AnythingV5 模型上完成方形及两种非方形实机画质验证，详见 [本机 NPU 验证记录](../../LOCAL-NPU-BRIDGE.md)。

分析模型默认 `gemini-3.8-flash`，令牌默认复用已保存的 TTS 令牌，也可单独设置；TTS 沿用原有配置。分析只使用 New API Chat Completions 兼容入口；如果中转不支持该入口或 JSON 输出约束，需要调整中转模型映射。角色卡配音库保存在用户私有目录 `xingzhan-synthesis/cards/<卡标识 SHA-256>/database.json`，音频单独保存到同目录。每张卡独立保存原文、分析、角色归纳、音色安排、情绪和逐段音频；群聊、临时文本分别隔离。审核修改自动保存，窗口关闭前刷入修改；当前卡可选择历史配音记录。已完成片段直接复用，继续生成仅请求缺失片段。旧全局记忆文件保留但不自动混入各张卡。TTS 的正文不再拼接生成指令，Gemini 3.8 用 speech_metadata.style 独立发送语气，其他模型仅提交正文。

源码：`index.js` 负责面板与独立生图流程，`media.js` 负责本地服务调用、配置与选词朗读，`system.js` 负责安卓语音转接与独立播放，`style.css` 负责界面，`manifest.json` 负责酒馆扩展注册。修改后运行 `node scripts/pack-synthesis.mjs` 生成插件 ZIP 和 APK 资源；APK 构建会自动打包。配置和聊天不随插件更新清除。

APK 启动只在自带插件包改变时更新插件文件，同一包重复启动保留插件的独立修改。APK 内置后端接口改变仍需要更新 APK；单独修改面板或前端行为可以修改插件目录后重新加载酒馆。

## Kokoro 交互式音色融合

在“星栈合成 → 安卓系统语音 → 交互式融合 Kokoro 音色”中选择 Kokoro 模型的 `voices.bin`、`voices.json`，分别指定音色 A、音色 B、融合比例和替换槽位，然后下载生成的两份文件。输入文件必须来自同一份模型；插件会校验音色编号及文件大小。当前实现按 510×256 的 float32 风格向量逐项插值，比例表示音色 A 的权重。

为兼容 Sherpa 现有的 `n_speakers` 元数据，融合结果替换一个现有槽位，不增加音色数量。替换前请备份原文件。Android 上的 Sherpa TTS 服务有独立存储空间，酒馆不能在运行时直接写入该目录或向引擎注入融合向量；需要先把模型文件复制到可选位置，再把下载后的 `voices.bin` 和 `voices.json` 放回对应模型目录，并重启或重新检测 Sherpa 引擎。成功加载后，融合音色会以目标槽位的新名称出现在音色列表中，可以用插件现有的试听和角色分配功能验证。

此流程已用一加 13T 上的 `kokoro-multi-lang-v1_1` 模型格式验证（103 个音色，`voices.bin` 53,790,720 字节）；验证只读取了手机模型副本，没有改写手机上的原始模型。当前仅验证这种文件布局；其他 Kokoro 模型若向量尺寸或索引格式不同，工具会拒绝处理。生成的文件需要用户手动复制回相应 Sherpa 模型目录并重新检测；目前没有运行时注入、自动替换或回滚功能。
